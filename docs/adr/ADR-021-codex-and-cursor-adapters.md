# ADR-021: Codex and Cursor adapters

- **Status:** Accepted (Sprint 10, S10-T01)
- **Date:** 2026-11-06
- **Related:** ADR-010 (hook forwarder and installation), ADR-008 (event contract), `docs/ADAPTER_CAPABILITIES.md`

## Context

Only agents with documented lifecycle hooks get an adapter. Codex CLI and Cursor both document user-level hooks. Their gaps differ from Claude Code's (no idle event in Codex, no needs-input event in Cursor), and the UI must show those gaps as unknown, never guess.

## Decision

- **Same forwarder.** `lullshift-desktop hook <adapter> --data-dir <dir>` with `<adapter>` one of `claude-code`, `codex`, `cursor`. Same 1 MiB / 2 s limits, zero-effect contract and redaction. The event mappers read only `session_id` (Cursor: `conversation_id`), the event name and lowercase enum hints. `user_email`, prompts, assistant messages and transcripts are not declared in the payload structs, so they are never held. Task-text capture is a separate, opt-in step (see "Prompt capture" below).
- **Shared installer** (`agent_adapters::hookfile`): backup first, atomic write that aborts on concurrent change, symlink/read-only refusal, idempotent merge, exact restore or removal of only Lullshift's entries, refusal (file untouched) when the file doesn't parse or has an unknown shape. Install records reuse the SQLite `adapter_installations` row per adapter id; no schema change.
- **Codex:** `$CODEX_HOME/hooks.json`, else `~/.codex/hooks.json`; never project files, never `notify`. Registers SessionStart, UserPromptSubmit, PostToolUse, PermissionRequest, Stop, Interrupt (all `async: true`, 2 s timeout) and SessionEnd (synchronous, 3 s timeout). `config.toml` is read, never written, for `[features] hooks = false` only, which makes status `hooks_disabled` when Lullshift's hooks are installed or partly installed (nothing installed stays `not_installed`). A relative `CODEX_HOME` is ignored. Hooks/settings files must be regular files of at most 1 MiB, with no duplicate JSON keys and no integers beyond 64 bits, or they are refused untouched (`settings_invalid`). PermissionRequest maps to `needs_attention`, Stop to `turn_ended`, SessionEnd to `session_ended`. **Interrupt maps to `turn_ended`** with `reason=interrupted`: `cancelled` is terminal in the reducer and the Codex session continues. The app tells the user that Codex requires reviewing and trusting new or changed hooks in `/hooks`, also after a repair; Lullshift can't observe that approval.
- **Cursor:** `~/.cursor/hooks.json` with `"version": 1` (another version is refused). Only non-blocking events, each with a 3 s timeout: sessionStart, beforeSubmitPrompt, postToolUse, afterAgentResponse, stop, sessionEnd and (added 2026-11-06, owner decision 23.2b) postToolUseFailure, subagentStop and preCompact. The Cursor hook documentation was re-checked on 2026-11-06: none of these three can block. `subagentStart` and `preToolUse` (and the other `before*` execution hooks) can block, so they are never registered; a test fails if one is added. Never `failClosed`. Nothing is written to stdout, so beforeSubmitPrompt lets the prompt through. Cursor never maps to `needs_attention` and doesn't declare the `attention` capability (Notification and PermissionRequest are documented as unsupported in Cursor).
  - **Mapping.** `postToolUseFailure`, `subagentStop` and `preCompact` map to `working`: a failed tool call doesn't fail the session. `stop` with status `error` is still `turn_ended` (status kept as a hint). `sessionEnd` with reason `error` maps to `failed` (owner decision 23.2); any other reason is `session_ended`. The reason is kept as a lowercase enum hint only; `error_message` and every other free-text field are not declared in the payload struct, so they are never read.
  - **Upgrades.** An install made with the original six hooks has no new entries and no stale ones, so status reports `partial`. Connecting again (install with the stored record) adds the missing three, never duplicates the existing six and never touches user hooks. Disconnect removes all nine.
- **Command line quoting (amended 2026-11-06, owner decision 23.4; was an allow-list).** Cursor (Windows: PowerShell) and Codex take a command string. It is built only from the app's own executable path and data directory, each absolute and in single quotes, and each path is escaped for the shell that runs it instead of being limited to a character set:
  - *POSIX sh* (macOS, Linux): single quotes make everything literal; an embedded `'` is written `'\''`.
  - *PowerShell* (Windows, with a leading `& `): single quotes make everything literal; an embedded quote is doubled. PowerShell reads U+2018, U+2019, U+201A and U+201B as quotes too, so those are doubled as well.
  - *Refused (`unsupported_path`, nothing written):* every control character (U+0000 to U+001F including NUL and newlines, U+007F, U+0080 to U+009F including NEL), U+2028 and U+2029, and bidirectional controls (U+061C, U+200E/F, U+202A to U+202E, U+2066 to U+2069), because no quoting carries newlines safely and bidi controls make a command read differently from how it runs. Non-Unicode paths are refused. For PowerShell also a trailing backslash (a native program would read `\"` as an escaped quote) and `[` or `]` in the program path (`& 'path'` resolves it as a wildcard pattern: found in testing with Windows PowerShell 5.1, an unbalanced bracket fails to run and a balanced one such as `a[bc]` could match another file).
  - *Legacy code page hazard (security review M2; owner decision 27.1, 2026-11-06: accepted residual risk; PowerShell form only).* If a host passes the command string through an ANSI (Windows-1252) path instead of UTF-16 or UTF-8, each UTF-8 byte is decoded on its own, and the bytes 0x82, 0x91, 0x92, 0x93 and 0x94 become the curly quotes U+201A, U+2018, U+2019, U+201C and U+201D. PowerShell reads the single-quote look-alikes as quote characters, so a path such as `C:\Users\Вася` (Cyrillic В is `D0 92`) could end its quoted string early and the rest would be parsed as code. The first version of this amendment failed closed and refused such paths. **Owner decision 27.1: allow them and accept the risk.** Install no longer refuses paths whose UTF-8 bytes include these values (letters such as В, Ђ, Â, Ñ, Ò, Ó, Ô); every other refusal stays. Residual risk: if a host really passes the command through a legacy cp1252 code page, these letters can become quote characters, which breaks the hook or, with a crafted folder name, changes what runs. A user name is not attacker-chosen in the normal case, and the usual hosts use UTF-8 or UTF-16 (the native-argv test proves a UTF-8 round trip with Cyrillic and Ñ paths). The hazard is documented for users in connecting-agents.md and troubleshooting.md. *Not done:* converting paths to 8.3 short names (`GetShortPathNameW`), because 8.3 generation is disabled on many volumes and a short path is unreadable in the hooks file. Claude Code uses exec form and is not affected. The sh form is unaffected.
  - *Wrapper layers (manual check).* The generated command is a PowerShell statement (`& '<exe>' hook ... --data-dir '<dir>'`) meant for `powershell -Command` or `pwsh -Command`. If a host wraps it in `cmd.exe /c "..."`, cmd.exe does not understand the call operator or the single quotes and the hook fails (it does not run anything else). Quoting cannot repair that, so it stays a manual check with real Cursor and Codex on Windows, ideally with a profile path that holds non-ASCII letters.
  - *Native argument round trip (test).* `crates/agent-adapters/tests/hook_native_argv.rs` builds a tiny native program that prints its arguments, runs the generated command through `pwsh -NoProfile -Command` and `powershell -NoProfile -Command` with spaces, an apostrophe, a curly quote look-alike and non-ASCII letters in both paths, and checks every argument arrives unchanged. It is skipped with a note when a shell or `rustc` is missing.
  - *Recognising our own entries* (status, repair, uninstall) parses the escaped first token back to the real path, so entries for paths with quotes are found and removed like any other. **Amended 2026-11-06 (review L1):** an entry is ours only if its command is exactly `<quoted lullshift exe> hook <adapter> --data-dir <one complete quoted token>` with nothing after that token, and the token equals this app's data directory. A user entry such as `...--data-dir '<dir>'; my-notify` is theirs and is never changed or removed. Entries that have the exact shape but name another data directory (a second build or profile) are not ours either: install does not replace them, Disconnect does not remove them, and status ignores them (reporting them as "needs repair" would offer a repair that can never fix them). Both builds can therefore be connected side by side; each removes only its own.
  - *Claude Code* is unaffected: it uses exec form (`command` plus an `args` array), with no shell.
  - *Tests:* 5000 random texts of special and Unicode characters round-trip through the quoting for both shells; the real shells are run on random texts and folders (sh where present, PowerShell 7 and Windows PowerShell where present; skipped with a note when missing) and must echo every argument back unchanged, with injection attempts (`'; cmd; '`, `$(...)`, backticks, curly-quote breakouts) staying text.
  - *Residual risk:* Cursor's and Codex's outer layer on Windows is undocumented. If it passes the string through another interpreter first (for example `cmd.exe` expanding `%VAR%`), a `%` in an install path could still be rewritten before PowerShell sees it. The failure mode is a hook that doesn't fire or points elsewhere, not extra code; it is logged as a manual check.
- **Prompt capture (added 2026-11-06, owner decision 23.8; extends ADR-013).** The existing opt-in is now per tool for `claude-code`, `codex` and `cursor`; each is off by default and has its own switch, consent dialog and marker file `<data-dir>/context-capture/<adapter>`.
  - *What is read.* Codex: `prompt` of `UserPromptSubmit`. Cursor: `prompt` of `beforeSubmitPrompt`. Nothing else, and only for that one event name; every other event returns before a prompt is looked at. `map_hook` (the event mapper) still never declares `prompt`. The prompt is the *intent* only: Codex and Cursor have no "what it's asking" text (Codex's `PermissionRequest` tool name is not used either).
  - *Gates.* Same two as Claude Code: the forwarder calls the prompt mapper only if the adapter's own marker exists (another tool's marker doesn't open it; a test passes a mapper that panics), and the app discards text unless the stored setting for that provider is on. Same limits (2,000 characters), cleaning and secret redaction, same storage (`session_context.captured_intent`; first prompt per session wins), same clear controls, nothing in the event log, logs or UI traces. Codex hooks are `async`, so capture adds no wait to Codex; the Cursor hook still writes nothing to stdout, so the prompt goes through.
  - *Not captured, ever:* Cursor `attachments`, `workspace_roots`, `user_email`, Codex `cwd`, `transcript_path`, tool data and assistant messages. No title capture for either tool.
  - *Tests:* per tool, "opt-in off: no context reaches the app", "another tool's marker doesn't open the gate", "opt-in on: only the prompt, cleaned, other hooks carry nothing and sentinel values from other fields never appear", app-side gate and clear tests, zero-effect contract with capture on.
- **Cursor payloads in the Claude Code path.** Cursor also runs hooks from `~/.claude/settings.json`. A payload carrying `cursor_version` is dropped by the Claude Code mapper (event, capture context and transcript reference), so it is never recorded as a `claude-code` session. It is not re-mapped to `cursor`: the shape Cursor sends to Claude-style hooks isn't documented, and the Cursor adapter's own hooks provide the real data.

## Consequences

- Codex hooks in sessions that were not trusted in `/hooks` send nothing; the app shows "Connected" with the trust note rather than claiming events flow.
- On Windows, the Codex shell isn't documented; the PowerShell form is used (same as Cursor). If Codex runs commands through another shell the hook fails silently (async, no effect on Codex) and the manual test in `docs/MANUAL_TESTS.md` should confirm.
- A user who disables Claude Code hooks inside Cursor loses nothing: Cursor's own adapter covers it.
