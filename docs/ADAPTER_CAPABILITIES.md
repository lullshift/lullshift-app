# Agent adapter capabilities

What each supported agent tells Lullshift, through its own documented lifecycle hooks. Anything marked "not available" is shown in the app as unknown, never guessed (PRD: represent unknown state honestly). Researched on 2026-11-06 from the official documentation linked below; re-check when an agent changes its hooks.

| Lullshift state | Claude Code | Codex CLI (hooks) | Cursor (hooks) | OpenCode 2.x (plugin, EXPERIMENTAL) |
|---|---|---|---|---|
| Session start | Supported (SessionStart) | Supported (SessionStart) | Supported (sessionStart); partial in the Cursor CLI | Supported (`session.created`); helper-agent sessions (with a parent) are not shown on their own |
| Prompt submitted / working | Supported (UserPromptSubmit, PostToolUse) | Supported (UserPromptSubmit, PostToolUse) | Supported (beforeSubmitPrompt, postToolUse, postToolUseFailure, subagentStop, preCompact, afterAgentResponse); partial in the CLI | Supported (`session.execution.started`, `session.tool.called`, `session.text.started`, `session.status` busy, `session.inbox.enqueued` for a user message, `permission.replied`); at most one per second per session |
| Needs input or permission | Supported (PermissionRequest, Notification) | Partial: PermissionRequest only, which fires only for commands that need approval; no idle or question event | Not available: no hook fires when Cursor waits for the user | Partial: `permission.asked` only; no idle or question event is in the plugin event stream |
| Turn ended | Supported (Stop, StopFailure) | Supported (Stop; Interrupt when the user stops a turn, shown as a turn end, not a cancelled session) | Supported (stop, with completed, aborted or error; all are turn ends) | Supported (`session.idle` or `session.execution.succeeded`, `session.execution.interrupted`; reported once per turn). `session.execution.failed` is shown as failed, and the idle that follows does not hide it |
| Session ended | Supported (SessionEnd) | Partial: SessionEnd also fires after 30 minutes idle and its reason is always "other" | Supported (sessionEnd, with a reason; reason `error` is shown as failed, other reasons as ended) | Partial: `session.deleted` only. A session closed without being deleted just goes stale |

## How Lullshift stays an observer

- **Claude Code:** hooks are registered with `async: true` and write nothing back.
- **Codex:** hooks are registered with `async: true` (2 s timeout), so they "can't block or rewrite". Status shows "hooks turned off in Codex" when `config.toml` has `[features] hooks = false` (only that key is read). The forwarder writes nothing to stdout and always exits 0. SessionEnd always runs synchronously, so it gets an explicit 3 s timeout (as Cursor). The "hooks turned off" status appears only when Lullshift's hooks are installed or partly installed. A relative `CODEX_HOME` is ignored. Codex asks the user to review and trust new or changed hooks in `/hooks` before they run, so installing or repairing needs one approval step inside Codex as well.
- **Cursor:** there is no async option. Lullshift registers only events that can't block: sessionStart, beforeSubmitPrompt, postToolUse, afterAgentResponse, stop, sessionEnd, postToolUseFailure, subagentStop and preCompact (the last three added 2026-11-06; an older install with six hooks shows as partly installed until the user connects again). It never registers subagentStart, preToolUse or the other before* hooks, because those can block (Cursor docs checked 2026-11-06). A failed tool call or a finished subagent maps to working, not failed. On beforeSubmitPrompt it writes nothing to stdout and exits 0, which lets the prompt through. It never registers permission or pre-tool hooks, writes no stdout and sets a short timeout. On Windows, Cursor runs hook commands through PowerShell. The command line is built only from the app's own executable and data folder, escaped for the shell that runs it (sh `'\''`, PowerShell doubled quotes including the Unicode look-alikes U+2018 to U+201B). Paths with control characters, line separators or bidi controls refuse install; for PowerShell so do `[`/`]` in the program path and a trailing backslash. Codex uses the same quoting. Details: ADR-021.
- - **OpenCode (experimental, OpenCode 2.x only):** there is no hook file. Lullshift writes one plugin file it owns, `lullshift-observer.js`, into OpenCode's global plugin folder (`$OPENCODE_CONFIG_DIR/plugins`, else `$XDG_CONFIG_HOME/opencode/plugins`, else `~/.config/opencode/plugins`, also on Windows), and nothing else: no OpenCode config is edited. The plugin exports only `{ id, setup }`, subscribes to `ctx.event.subscribe()`, registers no hook, returns nothing but a cleanup function, and wraps everything in try/catch. It spawns `lullshift-desktop hook opencode --data-dir <dir>` with an argument array (no shell), detached and never awaited, at most 8 at a time, and builds the JSON it sends field by field: the event kind, the session id and an enum hint. It never copies message text, tool inputs, file paths or errors. The plugin file embeds the executable path and data folder as ASCII-escaped string literals. `setup` returns at once, because OpenCode waits for plugin setup before it starts a session. Status: the file matching exactly is "installed", but the card stays "unknown" until the app has received an OpenCode event newer than the file; a different file of ours needs repair; a file with that name that Lullshift didn't write is never replaced or removed. OpenCode 1.x loads the same folder with a different plugin API and may show a plugin error for this file; Lullshift can't tell the version. Details: ADR-022.
- Lullshift never reads `user_email`, prompts or assistant messages from these payloads; only the session id, the event name and enum hints are kept. The one exception is the opt-in Task context (off by default, per tool, ADR-013 and ADR-021): with it on, the forwarder also reads the `prompt` of Codex's `UserPromptSubmit` and Cursor's `beforeSubmitPrompt`, and nothing else from those payloads. For OpenCode the prompt is the `text` of a user message (`session.inbox.enqueued`, item type `user`, confirmed in OpenCode 2.2.5's source types, not in its prose docs); the plugin includes it (cut to 4,000 characters) only when the consent marker file exists, and the forwarder checks the marker again.

## Known gaps and cautions

- **Cursor also runs Claude Code hooks.** Cursor loads hooks from `~/.claude/settings.json` by default, so Lullshift's Claude Code hooks may fire inside Cursor too. The forwarder recognises Cursor's payloads (a `cursor_version` field) and does not label them as Claude Code sessions. The exact payload Cursor sends to Claude-style hooks is not documented, so these events are dropped, not re-mapped; Cursor's own hooks provide the data (ADR-021).
- **Codex `notify`** (one command in `config.toml`, turn-complete only) is not used: it holds a single command, so installing Lullshift's would replace the user's own.
- **Undocumented interfaces are not used:** transcript formats, thread names, schemas from development branches.

- **OpenCode is experimental.** It rests on source-confirmed plugin types (OpenCode 2.2.5), not on documented event payloads, and the v2 plugin API is still moving; `experimental.idle` is not used because its shape "may still change". The global plugin folder is read from source, because the v2 docs only describe project folders. Re-check when OpenCode 2.x changes (ADR-022).

Decisions and the installer rules: ADR-021 (hooks), ADR-022 (OpenCode).
